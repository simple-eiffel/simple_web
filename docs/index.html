Overview

simple_web provides high-level HTTP APIs for Eiffel, supporting HTTP client operations, HTTP server development, resilience patterns, and ready-to-use AI API clients for Ollama, Claude, OpenAI, and Grok.

Part of the simple_* ecosystem of focused, single-purpose Eiffel libraries.

Quick Start

Installation

  1. Set environment variable: 
    export SIMPLE_EIFFEL=/d/prod
  2. Add to your ECF file: 
    <library name="simple_web" location="$SIMPLE_EIFFEL/simple_web/simple_web.ecf"/>

HTTP Server

local
    server: SIMPLE_WEB_SERVER
do
    create server.make (8080)
    server.on_get ("/api/users/{id}", agent handle_user)
    server.use (create {SIMPLE_WEB_CORS_MIDDLEWARE}.make)
    server.start
end

HTTP Client

local
    client: SIMPLE_WEB_CLIENT
do
    create client.make
    response := client.get ("https://api.example.com/users")
    response := client.post_json (url, '{"name": "Alice"}')
end

AI Client

local
    ollama: SIMPLE_WEB_OLLAMA_CLIENT
do
    create ollama
    response := ollama.generate ("llama3", "Hello!")
end

Resilience Policy

local
    policy: SIMPLE_RESILIENCE_POLICY
do
    create policy.make
    policy.with_retry (3)
          .with_circuit_breaker (5, 30)
          .with_timeout (10)
          .with_bulkhead (100)
    policy.execute_procedure (agent call_external_service)
end

Key Features

HTTP Client

Fluent request builder, libcurl & hybrid modes for reliable requests.

HTTP Server

Agent-based routing with {param} path parameters.

AI Clients

Ready-to-use clients for Ollama, Claude, OpenAI, and Grok.

Middleware

Logging, CORS, Auth (Bearer/Basic/API key) middleware.

Security

Input sanitization for XSS, path traversal, header injection.

JSON Support

Seamless JSON request/response handling with simple_json.

Resilience

Circuit breaker, bulkhead, retry with backoff, timeout, fallback patterns.

SCOOP mode

Since 0.2.0 simple_web serves under SCOOP. Supply a handler class rather than agents: SIMPLE_WEB_HANDLER_SERVER [MY_HANDLER] creates one MY_HANDLER (a SIMPLE_WEB_REQUEST_HANDLER) per request on the request's processor; its setup_routes fills a per-request SIMPLE_WEB_ROUTES with the familiar on_get / on_post / use calls. Process-wide strings travel through SIMPLE_WEB_SHARED (shared_put on the root before start, shared_item inside handlers). SIMPLE_WEB_SERVER and SIMPLE_WEB_QUICK stay thread-only and are excluded from SCOOP builds. Proof: target simple_web_scoop_tests.

Streaming and the peer address

SIMPLE_WEB_SERVER_RESPONSE can stream long-lived responses (Server-Sent Events and the like): send_stream_head (status, content_type) writes the status plus Cache-Control: no-cache and Connection: close (no Content-Length - the connection's close delimits the body), then send_chunk writes and flushes each piece; is_streaming tells the story, and the contracts enforce head-once, chunks-only-after-head. A raising connector's failed write is swallowed into is_streaming := False; EWF's standalone connector never reports a hung-up client, so bound a stream's lifetime in the application. In mock mode the head lands in mock_headers and chunks append to mock_body.

SIMPLE_WEB_SERVER_REQUEST.remote_address reports the connection's peer IP (the CGI REMOTE_ADDR meta variable; empty when unavailable), with set_mock_remote_address for tests - the honest input for per-client limits. Real-socket proof: the /peer and /stream routes in the SCOOP suite.
